# WPE WebKit на OpenHarmony: устройство и состав

Заметка на рубеже: движок собран, перенесён в `/system`, показывает страницы
на экране через собственную площадку вывода. Разрешение имён работает через
штатную службу OpenHarmony.

---

## Что получилось

Обозреватель — обычный процесс на машине. Он заводит себе окно у службы
отрисовки, движок рисует в него страницу, сеть идёт через `libsoup` с
защищёнными соединениями, имена разрешает `netsysnative`.

```
./wpe.sh deps      собрать 17 зависимостей под OpenHarmony
./wpe.sh engine    собрать WPE WebKit 2.54
./wpe.sh platform  собрать площадку вывода
./wpe.sh deploy    перенести всё в /system
WPE_PLATFORM=ohos bash smoke.sh run https://wpewebkit.org
```

## Кто за что отвечает во время работы

### Процессы

```
         ┌──────────────────────────────────────────┐
         │  обозреватель (наш процесс)              │
         │                                          │
         │  ┌────────────────────────────────────┐  │
         │  │ libarkvm_ohos_window.z.so          │  │  заводит окно
         │  │   RSSurfaceNode → номер поверхности│  │
         │  └────────────────────────────────────┘  │
         │  ┌────────────────────────────────────┐  │
         │  │ libWPEPlatformOHOS.so (площадка)   │  │  показывает кадры
         │  │   номер → OHNativeWindow → EGL     │  │
         │  └────────────────────────────────────┘  │
         │  ┌────────────────────────────────────┐  │
         │  │ libWPEWebKit-2.0.so                │  │  управление
         │  └────────────────────────────────────┘  │
         └───────────┬──────────────────┬───────────┘
                     │                  │
         ┌───────────▼──────┐  ┌────────▼─────────┐
         │ WPEWebProcess    │  │ WPENetworkProcess│
         │ разбор разметки, │  │ обмен по сети,   │
         │ сценарии, вёрстка│  │ печенье, хранение│
         │ отрисовка кадра  │  │                  │
         └──────────────────┘  └──────────────────┘
```

Разделение придумано не нами — так устроен WebKit. Страницу разбирает и
рисует отдельный процесс, сетью ведает ещё один, а наш держит окно и
решает, что показывать. Падение разборщика не роняет обозреватель.

### Службы OpenHarmony, на которые мы опираемся

| Служба | Зачем |
|---|---|
| `render_service` | даёт поверхность и складывает слои на экран |
| `samgr` | через него службы находят друг друга |
| `netsysnative` (1158) | разрешение имён: musl стучится в её сокет `dnsproxyd` |
| `netmanager` (1151) | сообщает первой, какими серверами имён пользоваться |

### Путь кадра

1. `WPEWebProcess` рисует страницу и отдаёт готовый кадр через
   межпроцессный обмен.
2. Площадка получает его в `render_buffer`.
3. Пробует превратить в картинку для EGL (`wpe_buffer_import_to_egl_image`)
   — это даром, но работает только для кадров в `dma-buf`.
4. Если не вышло — берёт точки (`wpe_buffer_import_to_pixels`) и заливает
   их в полотно. Медленнее, но всегда.
5. Натягивает полотно на прямоугольник во всё окно и отдаёт кадр системе
   (`eglSwapBuffers`).

Сейчас идёт второй путь: мы отключили `gbm`, и предпочитаемых видов кадров
площадка не объявляет, поэтому движок отдаёт кадры в общей памяти. Это
первое, что стоит ускорить.

## Ловушки, на которые мы уже наступили

Это самое ценное в заметке: каждая из них стоила времени.

**Стандартная библиотека C++.** Довод `-stdlib=libc++` для цели OpenHarmony
означает не «возьми libc++», а «возьми **их** libc++» — пятнадцатой версии.
Нужно `-nostdinc++ -nostdlib++` и называть свои библиотеки прямо. И не
добавлять `$NDK/llvm/lib/$TARGET` в пути поиска: там лежит их
`libc++_shared.so`.

**Заголовки ядра.** В пакете OpenHarmony они из набора для Android и
повторно объявляют `sockaddr_storage`. Лечится подкладкой `shim/linux/socket.h`.

**`RTLD_GLOBAL` при подгрузке.** Вводит имена подгружаемой библиотеки и
всего, что за ней, в общий круг — чужая libc++ начинает перебивать нашу.
Подгружать надо с одним только `RTLD_NOW`.

**Номер поверхности внутрипроцессный.** `SurfaceUtils` хранит их в памяти
процесса. Заводить окно обязан тот, кто в нём рисует.

**Размер буфера до поверхности EGL.** `SET_BUFFER_GEOMETRY` надо вызвать
**до** `eglCreateWindowSurface`, иначе слой связи с Vulkan не заведёт ни
одного образа для обмена.

**Виды в подключаемой части.** GIO выгружает часть сразу после просмотра
каталога, если виды не привязаны к ней через `G_DEFINE_DYNAMIC_TYPE` и
`register_type`. Иначе первое создание объекта падает.

**Начало отсчёта в OpenGL — левый нижний угол.** Область рисования меньше
окна уводит картинку вниз-влево.

**Разрешение имён.** musl в OpenHarmony не читает `/etc/resolv.conf` вовсе:
он стучится в `/dev/unix/socket/dnsproxyd`. Без службы 1158 имена не
разрешаются, и никакие настройки это не меняют.

**Утилиты из склада.** В `stage/system/bin` лежат сборки под OpenHarmony;
если оставить их на виду, CMake возьмёт оттуда `glib-compile-resources`
и сборка встанет на «not found».

## Что в сборку не входит

Отключено намеренно: звук и видео целиком (а с ними GStreamer — самая
тяжёлая зависимость), WebRTC, площадки DRM и Wayland, XSLT, JPEG-XL и AVIF,
проверка правописания, речевой вывод, доступность через ATK, песочница на
bubblewrap, игровые устройства. Подробности — в `README.md`.

## Что дальше

**Ускорить показ кадров.** Сейчас кадр переписывается из общей памяти в
полотно на каждом шаге. Если объявить площадке предпочитаемые виды кадров
через `dma-buf` (у нас есть `EGL_EXT_image_dma_buf_import`), движок начнёт
отдавать кадры без переписывания.

**Ввод.** Нажатия и прикосновения пока никуда не передаются. Нужна связь
`multimodalinput` → `wpe_view_event`.

**Настоящее окно.** Сейчас это самостоятельный слой поверх оболочки: без
заголовка, без перемещения, без порядка наложения. Варианта два — окно от
оконного распорядителя (`Window::Create`) или приложение на ArkTS с
`XComponent`.

**Внешность.** В дереве есть `applications/browser` — готовый обозреватель
на ArkTS со строкой адреса, вкладками, закладками. На `webview` опирается
**один файл**: `feature/web/src/main/ets/BrowsePageView.ets`, строка 1430.
Если заменить там свойство `Web` на `XComponent` поверх нашего движка,
получится настоящий обозреватель без рисования внешности с нуля.

**Площадка принимает окно снаружи.** Это уже заложено: если задана
переменная `WPE_OHOS_SURFACE_ID`, площадка берёт готовый номер вместо того,
чтобы заводить окно самой. В приложении на ArkTS номер придёт от
`XComponent`, и менять в площадке ничего не придётся.
